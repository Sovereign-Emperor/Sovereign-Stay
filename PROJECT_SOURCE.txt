PROJECT SOVEREIGN: STUDENT ACCOMMODATION MARKETPLACE
MASTER PROJECT SOURCE

PROJECT STATUS
This is an active startup/product project. Treat this document as the core source of truth for the project.

==================================================
1. THE PROBLEM
==================================================

Students searching for accommodation, especially around universities and tertiary institutions in Ghana, face a painful and inefficient process.

Common problems include:

- Difficulty discovering available hostels, apartments, rooms, and other accommodation.
- Information is scattered across WhatsApp, Facebook, TikTok, word of mouth, agents, signs, and personal contacts.
- Students often don't know whether a room is actually available.
- Students may have to physically travel to multiple locations just to inspect options.
- Photos and videos are often unavailable, outdated, or insufficient.
- Location information can be unclear.
- Prices are difficult to compare.
- Facilities and room conditions are difficult to compare.
- Students can waste significant time and transportation money searching.
- Students may arrive at a property only to discover that it is full, unsuitable, too expensive, or different from what they expected.
- There is a lack of centralized, trustworthy, student-focused accommodation discovery.

CORE PROBLEM STATEMENT:

"Students should not have to physically hunt around a city just to discover where they can live."

==================================================
2. THE PRODUCT VISION
==================================================

Build a student-focused accommodation marketplace that makes finding accommodation as easy as discovering content on TikTok.

A student should be able to open the platform and immediately discover available accommodation through visual listings.

The experience should feel like:

TikTok + Airbnb + Facebook Marketplace
but specifically optimized for student accommodation in Ghana.

The platform should allow students to:

- Discover accommodation visually.
- Scroll through listings.
- Watch photos and short video walkthroughs.
- Search by school, area, location, price, and accommodation type.
- Filter according to their requirements.
- See accurate accommodation details.
- See approximate distance from campus.
- View location information/maps.
- Compare options.
- Check availability.
- Contact the owner/manager/agent.
- Request a viewing.
- Eventually reserve or pay securely through the platform.

Accommodation providers should be able to:

- Create listings.
- Upload photos and videos.
- Add prices.
- Describe rooms.
- Specify facilities.
- Set availability.
- Provide location information.
- Receive enquiries.
- Manage their listings.
- Eventually receive bookings/payments.

5. CORE PRODUCT LOOP
==================================================

The fundamental loop is:

PROPERTY OWNER LISTS PROPERTY
        ↓
STUDENT DISCOVERS PROPERTY
        ↓
STUDENT WATCHES / VIEWS LISTING
        ↓
STUDENT FILTERS / COMPARES
        ↓
STUDENT CHECKS LOCATION + DETAILS
        ↓
STUDENT CONTACTS OWNER
        ↓
STUDENT REQUESTS VIEWING
        ↓
STUDENT SECURES ACCOMMODATION

The platform succeeds when it makes this loop dramatically faster and more trustworthy than the traditional process.

8. TRUST IS A CORE FEATURE
==================================================

Trust is not an optional feature.

A major risk is fake, outdated, misleading, or unavailable listings.

Therefore the platform should eventually support:

- Verified providers.
- Verified properties.
- Availability verification.
- Report listing.
- Reviews.
- User ratings.
- Last-updated timestamp.
- Property verification status.
- Fraud detection.
- Admin moderation.

A listing should communicate clearly:

"Is this real?"
"Is it available?"
"Is the information current?"
"Can I trust this provider?"

Airbnb:

- Location.

- Location discovery.

Create an original student-accommodation experience optimized for Ghana.

==================================================
12. DEVELOPMENT PRINCIPLES
==================================================

Build from the smallest useful version.

Do not build unnecessary features just because they sound impressive.

Every feature must answer:

"Does this make accommodation discovery easier, safer, faster, or more useful?"

Prioritize:

1. Core user problem.
2. User experience.
3. Data quality.
4. Trust.
5. Performance.
6. Simplicity.
7. Scalability.

Avoid premature complexity.

==================================================
13. VALIDATION PRINCIPLE
==================================================

Before investing heavily in development, validate the problem.

Research:

- Students.
- Hostel owners.
- Landlords.
- Property managers.
- Agents.

Questions should focus on actual behavior rather than hypothetical opinions.

Find out:

- How students currently search.
- How long searching takes.
- What information they struggle to find.
- How much transportation/search costs them.
- How they determine whether a listing is trustworthy.
- How property owners currently advertise.
- How owners manage vacancies.
- Whether owners would adopt the platform.

The objective is to discover evidence of real demand.

==================================================
17. DECISION FILTER
==================================================

Whenever making a product, design, technology, marketing, or business decision, ask:

1. Does this solve the accommodation problem?
2. Does this improve the student experience?
3. Does this help providers list and fill vacancies?
4. Does this improve trust?
5. Does this help us validate the business?
6. Is this necessary RIGHT NOW?
7. Can we build a simpler version first?

If the answer to most of these is NO, the feature should probably not be built yet.
